══════════════════════════════════════════════
  ZMAN — RAILWAY DEPLOY (its own project, alongside dad's site)
══════════════════════════════════════════════

GOAL: Run Zman on the Railway you bought WITHOUT touching dad's site.

KEY IDEA: In Railway, each PROJECT is fully isolated — its own build, its own
variables, its own domain, its own volume. Two separate projects can never
override each other. So the rule is simply:

  → Create a NEW, SEPARATE Railway project for Zman.
  → Do NOT add Zman as a service inside dad's existing project.
  → Do NOT reuse dad's domain, secrets, or GitHub auto-deploy hook.

──────────────────────────────────────────────
  1. SECRETS — generate FRESH ones (never reuse dad's)
──────────────────────────────────────────────
Do NOT paste secrets that live in any other project. Generate new ones.

PowerShell:
  # AUTH_SECRET (any long random hex)
  [Convert]::ToHexString((1..32 | %{ Get-Random -Max 256 })).ToLower()
  # ENCRYPTION_KEY (must be exactly 64 hex chars)
  [Convert]::ToHexString((1..32 | %{ Get-Random -Max 256 })).ToLower()

Node (anywhere):
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

──────────────────────────────────────────────
  2. VARIABLES — paste into the NEW Zman project → Variables
──────────────────────────────────────────────
AUTH_SECRET=<fresh value from step 1 — unique to this project>
ENCRYPTION_KEY=<fresh 64-hex value from step 1>

# AI provider — set ONE of these:
OPENAI_API_KEY=sk-...                 # or
MINIMAX_API_KEY=sk-cp-...

# Web push (browser PWA). Generate with: npx web-push generate-vapid-keys
NEXT_PUBLIC_VAPID_PUBLIC_KEY=<vapid public>
VAPID_PRIVATE_KEY=<vapid private>

# URLs — fill in AFTER the first deploy gives you this project's own URL:
NEXT_PUBLIC_APP_URL=https://<your-new-zman>.up.railway.app
CAPACITOR_SERVER_URL=https://<your-new-zman>.up.railway.app

# Optional (native push): FIREBASE_SERVICE_ACCOUNT=<service-account JSON>

──────────────────────────────────────────────
  3. VOLUME — required, or user data resets each deploy
──────────────────────────────────────────────
New Zman project → Volumes → Add Volume → Mount Path: /app/data
(This volume belongs to the Zman project only. Dad's data lives in dad's own
project/volume — they never mix.)

──────────────────────────────────────────────
  4. STEPS
──────────────────────────────────────────────
1. railway.app → Login → New Project → Deploy from GitHub repo → select Zman's
   repo (alon0581/zman). This is a DIFFERENT project from dad's site.
2. Variables → paste everything from step 2 (using fresh secrets from step 1).
3. Volumes → Add Volume → Mount Path: /app/data.
4. Deploy. Copy the generated URL.
5. Set NEXT_PUBLIC_APP_URL and CAPACITOR_SERVER_URL to that URL → redeploy.
6. (Native apps only) rebuild with CAPACITOR_SERVER_URL set so the iOS/Android
   shell loads this Zman project, not any other.

──────────────────────────────────────────────
  WHY THEY WON'T OVERRIDE EACH OTHER
──────────────────────────────────────────────
• Separate projects = separate builds, env vars, volumes, domains.
• Railway's GitHub auto-deploy is configured PER service: dad's service watches
  dad's repo/branch; Zman's service watches Zman's repo/branch. Don't point both
  services at the same repo and you're safe.
• If you use custom domains, give each project a DIFFERENT domain.
